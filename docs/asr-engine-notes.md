# sherpa-onnx 系 ASR エンジンの実測と既定値

`sensevoice-onnx`・`parakeet-onnx`・`cohere-asr-onnx`・`funasr-nano-onnx` の精度・速度の実測値と、既定値の根拠をまとめます。
測定環境は Windows 11・Intel Core Ultra 9 275HX です。

## 精度と速度（JSUT 20 発話・平均音声長 3.51 秒）

| 指標 | 定義 |
|---|---|
| CER | 正解文（句読点あり）に対する文字誤り率 |
| 平均 ms | 1 発話あたりの認識時間の平均。モデルのウォームアップを含む 1 発話目を除く |
| 最悪 ms | 20 発話中の最大値。対話用途では体感上の応答性をこちらが左右する |

いずれも CPU・8 スレッドでの測定です。

| エンジン | CER | 平均 ms | 最悪 ms | 備考 |
|---|---:|---:|---:|---|
| `funasr-nano-onnx` | 0.088 | 629 | 906 | 最高精度。LLM デコーダのため遅延のばらつきが大きい |
| `sensevoice-onnx` | 0.090 | 86 | 123 | 精度と速度を両立。この 4 エンジン中の第一候補 |
| `cohere-asr-onnx` | 0.105 | 632 | 799 | 14 言語対応。多言語の入力がある場合に有効 |
| `parakeet-onnx` | 0.121 | 157 | 193 | CTC のみのエクスポートのため精度は控えめ |
| `qwen3-asr-onnx` | 0.111 | 2146 | 9753 | |
| `nemotron-onnx`（唯一の真のストリーミング） | 0.173〜0.192 | 約 400 | | |

各エンジンは、設定画面の「エンジン管理」で選択して「適用」すると導入されます（`setup_assets.ps1` の
`-Only SenseVoiceModel` などが実行されます）。

## 既定値の根拠

いずれも上記の 20 発話での実測に基づきます。

### 実行デバイス：4 エンジンとも CPU

配布されている int8 モデルは動的量子化のため CUDA カーネルが効かず、GPU のほうが遅いうえ最悪値も大きくなります
（`sensevoice-onnx`：CPU 86 ms / 最悪 123 ms に対し、CUDA 107 ms / 最悪 2315 ms）。GPU を試す価値があるのは、
fp32 のモデルに差し替えた場合のみです。

### ITN（句読点・数字表記）：有効

正解文に句読点があるため、ITN を有効にしたほうが CER が下がります（`sensevoice-onnx`：0.153 → 0.090）。
後段の LLM に渡す文としても読みやすくなります。

### `funasr-nano-onnx` の Max new tokens：128

ライブラリの既定値は 512 です。自己回帰デコーダのため、生成数の上限がそのまま最悪遅延の上限になります。
PyTorch 実装では最悪 2473 ms でしたが、この設定で 906 ms に収まります。

### `sensevoice-onnx` のモデル：`...-int8-2024-07-17`

> [!WARNING]
> 同じ命名の `2025-09-09` は ASLP-lab/WSYue-ASR による広東語のファインチューン版で、日本語音声を簡体字で
> 書き起こします（同梱の ja.wav でも「便当制」などと出力され、CER は 0.79）。必ず `2024-07-17` を使用してください。

### 運用：VAD で区切って一括投入

4 エンジンとも非ストリーミング認識のため、VAD で発話を区切って一括で投入する運用が前提です。
ASR 共通設定の Pseudo streaming を短い間隔で実行すると、発話全体の再推論を繰り返すうえ精度も低下します
（720 ms チャンクで CER 0.153 → 0.290、20 発話中 7 発話で 0.15 以上悪化）。
