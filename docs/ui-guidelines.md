# UI ガイドライン

Qt アプリ（PySide6）と Web UI に共通する、画面の設計方針と表示文言の規則をまとめる。両者は同じ暗色の配色と
同じ画面構成にそろえ、表示する文言は [表記と用語](#表記と用語) に従う。

## 設計方針

### 色

`src/maai_sds/gui/theme.py` の `TOKENS` と `web/app/app.css` は同じ色の値を使う。Web では多くを `:root` の変数に置き、
input と idle は該当するルールに直接書いている（panel は `:root` の `--panel` が半透明で、不透明の値は `--panel-solid`）。
一方を変更した場合は、もう一方も合わせて変更する。

| 名前 | 値 | 用途 |
| --- | --- | --- |
| bg | `#14171d` | 画面の背景 |
| panel | `#1b212b` | カード（グループ枠）の背景 |
| panel_2 | `#232b38` | ボタン・ポップアップの背景 |
| input | `#11161e` | 入力欄の背景 |
| line | `#333d4d` | 枠線 |
| text | `#e6e9ef` | 本文 |
| muted | `#97a3b6` | 補足・小見出し・状態表示 |
| accent | `#4f9cf9` | 主ボタン・選択中・フォーカス |
| ok / warn / err | `#55c98a` / `#e6b455` / `#e2685f` | 稼働 / 起動中 / 異常 |
| idle | `#5b6577` | 停止 |

モジュール状態のランプには `STATE_COLORS`（停止・起動中・稼働・異常）を使う。

### 書体と形状

| 対象 | 規定 |
| --- | --- |
| 文字 | Yu Gothic UI（ない場合は Segoe UI / Meiryo UI）、10pt（Web は 13px） |
| カード | 角の丸み 8px、枠線 1px |
| ボタン・入力欄 | 角の丸み 4px |
| 主ボタン | その画面で最も頻繁に使う操作（「MMDAgent-EXを起動」「音声対話開始」など）。accent で塗る。Qt は `setProperty("role", "primary")`、Web は `class="primary"` |
| 補足の小さな文字 | Qt は `setProperty("role", "caption")`（状態表示は `"status"`） |

### メイン画面の構成

#### ヘッダー

アプリ名と、対話サーバー・MMDAgent-EX・音声対話の状態（色付きの印）を表示する。右端には状態メッセージを置く。

#### 左列：会話

縦長の欄とする（Qt は既定のウィンドウサイズ 980×850 で幅約 510px、Web は幅の上限 560px）。履歴（新しいものが下に追加される）の下に生成中の応答を置き、上から下へ読めるようにする。

#### 右列：操作

幅は 420px に固定し、使う順に上から配置する。スクロールなしで収まるよう、説明文はツールチップに移し、状態と遅延は 1 行、テストとツールのボタンも 1 行に並べる。

1. MMDAgent-EX：起動・停止、プロセスと接続の状態
2. 音声対話：大きな「音声対話開始」ボタン、自動で起動するモジュールの説明、終了・割り込み・詳細設定、状態と遅延
3. モジュール状態：一括起動は右上に小さく配置。先頭行は対話サーバー（後述）
4. 設定・テスト：「テスト」「設定」「ツール」

#### 対話サーバーの行

対話サーバーは、ASR・LLM・TTS・MaAI を動かすバックエンドのプロセスである。

- ▶ / ■ で起動・停止する。■ で停止した後は、▶ を押すか、モジュールの起動または音声対話の開始を行うまで自動では再起動しない。
- Qt の Docker モードでは、起動スクリプトが渡した compose で orchestrator サービスを up / stop する。
- Web では Web サーバーの子プロセスを起動・停止する（Web サーバー自体は対象外）。

#### ローカル / Docker の選択

- Qt では行の右端で「ローカル」/「Docker」を選択できる。選択すると確認のうえ GUI を開き直す。設定ファイル・パスの変換・選択できるエンジンが起動時のモードで決まるためである。
- 選択はユーザーの設定フォルダーの `launch.json` に保存し、次回の起動でも使う（Qt と Web で共通）。`--remote-orchestrator` / `--dialog-server` / `start_qt_docker.ps1` の指定が優先される。
- ホストで動かす Web UI も同じ選択を持つ。選択すると Web サーバーを開き直し、ページを再読み込みする。
- Docker を選ぶと、Web サーバーは compose の orchestrator に接続し、設定には `controller_config.docker.json`（コンテナのパス）を使う。
  - Web サーバー自身がファイルを読み書きする場合（MDF・ファイル参照・WAV 再生）は、ホストのパスに変換する。
  - 参照ダイアログには、コンテナから読めるフォルダーだけをコンテナのパスで表示する（MMDAgent-EX の実行ファイルはホストのパスで選ぶ）。
  - マイクはブラウザのマイクに固定し、エンジン管理は使用できない。
- コンテナ内で動かす Web UI には、この選択を表示しない。

利用者向けの切り替え手順は [running.md](./running.md) にある。

### 設定・テストのウィンドウ

設定・テストの画面は 1 つのウィンドウにまとめ、左の一覧で切り替える（Qt は `gui/settings_hub.py`、Web は設定画面の左の一覧。並びは共通）。コンソール・「MaAIプロット」・頷きモーションの波形は横に並べて見る用途があるため、別ウィンドウとする。Web では `?view=<画面ID>` で特定の画面を直接開ける。

音声対話の細かな設定（開始・終了時の発話、割り込み、LLM→TTS）は「音声対話の詳細設定」画面に置き、メイン画面には出さない。

### 設定・テストの各画面

- 頻繁に使う項目を上に置く。しきい値・秒数・スレッド数などの細かな調整項目は、折りたためる「詳細設定（…）」の枠（`gui/collapsible.py` の `CollapsibleSection`）にまとめる。項目を隠すのではなく一段奥に置くだけであり、Web では同じグループの行としてそのまま表示する。
- 中身が表示されない枠は、枠ごと非表示にする（例：TTS の「モデル設定（対応エンジンのみ）」は Kokoro のときだけ表示）。
- 各画面で最も頻繁に使う操作（起動・送信など）は主ボタンとする。

## 表記と用語

Qt アプリと Web UI で共通に使う、日本語表記の基準である。適用対象は利用者に表示する文言だけで、設定キー・ウィジェットの属性名・保存値・API の値は対象外とする。

### 表記の規則

| 規則 | 例 |
| --- | --- |
| 製品名・モデル名は正式表記を保つ | `MMDAgent-EX`、`VOICEVOX`、`sherpa-onnx`、`LM Studio`、`MaAI` |
| 確立した略語は英字のまま使う | `ASR`、`LLM`、`TTS`、`VAD`、`AEC`、`API`、`ONNX`、`MDF`、`WAV` |
| モデルを構成するファイルの名称は英語のまま使う | `Tokens`、`Encoder`、`Decoder`、`Joiner`、`Tokenizer` |
| エンジンごとの画面の項目名にはエンジン名を付けない（見出しに 1 回だけ示す） | `エンジン設定（sherpa-onnx）` |
| 日本語と英字の境界に半角スペースを入れない | `ASRテスト`、`MaAIモデル設定`、`WebSocketパスワード` |
| 単位は全角括弧で示す | `時間（秒）`、`フレームレート（Hz）`、`間隔（ms）` |

補足：

- 製品名自体に含まれる空白は維持する（例：`LM Studio`）。英語だけで構成する技術値やコード断片には、空白の規則を適用しない。
- 設定項目の英語名や内部キーを、説明なしで表示ラベルに使わない。内部キーは必要に応じてツールチップの `キー：` 行に示す。
- ウィンドウを開くボタンと、そのウィンドウのタイトルは同じ名称にする。
- 三点リーダー `…` は省略を表す場合にだけ使う。文字幅の不足を補う目的で `...` は使わない。
- `MaAI` を正式表記とし、`MAAI`・`Maai` は使わない。

### 変更しない値

エンジン名・バックエンド名・入力モード・実行デバイスなど、コードが文字列で比較する選択肢は、表示上も変更しない。例：`LM Studio`、`OpenAI`、`Custom`、`mic`、`wav`、`tcp`、`GPU (cuda)`、`CPU (int8)`。表示名と保存値を分離済みの項目は、保存値を変えずに日本語の表示名を使える。
